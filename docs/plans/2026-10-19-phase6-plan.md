# Phase 6 plan: on-demand AWS deploy

Decisions and evidence: [`docs/prior-art/2026-10-19-phase6-deploy.md`](../prior-art/2026-10-19-phase6-deploy.md).

## Done when
`make up` brings up a working demo at the CloudFront URL (sign in, inbox, approve, analytics updates through real SNS and SQS), `make down` removes everything billed by the hour while the site stays up and says the demo is offline, and CI builds, pushes, and deploys through Flux without anyone touching the cluster.

## Shape

```
viewer ──https──► CloudFront ──/*──────► S3 (React build, OAC)
                      │
                      └──/api/*── VPC origin ──http──► internal ALB (private subnets)
                                                          │ NodePort 30080
                                    EKS 1.37, 2× t4g.small (public subnets, no inbound)
                                    api · sidekiq · events   (Flux syncs deploy/production)
                                          │            │            │
                                   RDS Postgres 17   Valkey 8   SNS ─► SQS (+DLQ)
                                   (private)        (private, TLS)      │
                                                                   S3 analytics export
```

## Stacks

| Stack | Lifetime | Contents |
| --- | --- | --- |
| `bin/tf-bootstrap` | once | State bucket `cubby-tfstate-731956852586` (versioned, S3-native locking) |
| `infra/terraform/base` | always | ECR, web bucket, CloudFront + SPA function, analytics bucket, GitHub OIDC deploy role, alerts topic, $50 budget |
| `infra/terraform/cluster` | `make up` / `make down` | VPC, EKS + addons, node group, internal ALB, VPC origin, RDS, Valkey, SNS/SQS with policies, Pod Identity roles, config and secrets, Flux, alarms |

`make up` applies the cluster, then writes the ALB and VPC origin into the base stack's `api_origin` variable so CloudFront routes `/api/*`. `make down` reverses that order, because CloudFront must release the VPC origin before it can be deleted.

## Phase 3 deploy checklist

| Item | Done |
| --- | --- |
| Real viewer IP for rate limits | `ViewerAddress` middleware reads `CloudFront-Viewer-Address`, trusted because the ALB is reachable only through the VPC origin |
| Shared rate-limit store | `config.cache_store = :redis_cache_store` on Valkey |
| `APP_ORIGINS` | Set to the CloudFront origin by Terraform |
| Sec-Fetch-Site check behind CloudFront | All viewer headers are forwarded; re-checked live |
| Password change, sign out everywhere | Deferred: the demo directors are shared accounts, so a visitor changing the password would lock everyone else out. Required before any real user |

## Steps
1. Rails production config: viewer address, Redis cache, demo seeds behind `CUBBY_DEMO=1` with a generated password, faker in the default group.
2. Base stack, applied. CI jobs: arm64 image to ECR plus a tag bump commit; web build to S3 plus invalidation; Terraform and kustomize checks.
3. Cluster stack and `deploy/production` manifests; `make up`.
4. Live checks (O1 to O7 in the record), independent security review, `make down` check of what remains.
